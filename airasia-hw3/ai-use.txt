HW3 - PHP/SQL Integration (Gift Card Management)
=====================================================================

1. AI tool used
Claude Code (Anthropic, Claude Opus 5.5) in the VS Code extension.

2. Prompts used
- "Help me ensure that I met all of the requirements for this assignment" (I attached the HW3 assignment PDF.
  The AI also read the AirAsia Requirements Document for the table and
  column names.)

3. How AI supported my work
AI converted my HW2 static pages into PHP pages backed by SQLite and PDO.
It wrote these files:
- schema.sql and seed.sql, using the GIFTCARD and ACCOUNT column names
  from the requirements document
- Shared header, nav, and footer templates
- A shared PDO connection (includes/db.php)
- Reusable validation functions (includes/validation.php)
- One form partial shared by the add and update pages
- The validation test harness
AI also helped draft the README traceability table and the test report.
It ran the test harness and tested every page against a copy of the
database, including invalid ids, altered form values, and HTML/script
text in a card name.

4. One AI suggestion tested, revised, or rejected
The first draft of the shared Gift Card form used the "novalidate"
attribute so that invalid values would always reach the server during
testing. That turned off the browser's own checks (required, min, step),
which the assignment says improve the user experience. I revised the form
to remove "novalidate". Server-side validation is unchanged. Altered or
invalid requests are still tested by sending them directly to the server
(test T07).

Another suggestion I kept on purpose:
- The requirements document says card-update forwards to card-list and
  card-delete needs no HTML display.
- The HW3 assignment requires card-update to show the updated details
  and card-delete to show a POST confirmation page.
- I followed the HW3 workflow for both, because the assignment states
  that workflow explicitly.

5. How I verified the final code and database behavior
- Rebuilt rewards.db from schema.sql and seed.sql and confirmed 5 ACCOUNT
  rows and 20 GIFTCARD rows with sqlite3.
- Ran tests/validation-tests.php: 27 of 27 tests PASS.
- Ran every workflow (list, details, add, update, delete) and checked the
  database after each change with sqlite3 SELECT queries.
- Tried invalid and altered input and bad card_id values, and confirmed
  that errors were shown and no records changed.
- Confirmed that a GET request to card-delete.php never deletes a record.
- All results are documented in test-report.md.
